1. AI Features - XiaoZhi Firmware AI Technology Integration Guide
Edge Intelligence + Cloud LLM + IoT

Xiaozhi AI operates on a Hybrid AI Inference Architecture: edge intelligence handles instantaneous local keyword filtering and voice wake-up on dual ESP32-S3 LX7 cores at 240MHz, while natural language reasoning, vision multi-modality, and TTS speech synthesis are offloaded to high-performance cloud LLMs.

1️⃣ Offline Voice Wake-up AI
Powered by Espressif Speech Recognition. Default wake word: "你好小智" (<200ms latency, <5mA standby power). Supports 26+ official vocabulary phrases ("Hi ESP", "Smart Home", etc.) configured via idf.py menuconfig.
2️⃣ Multilingual ASR & Locales (v2.0)
Captures 16kHz mono audio via INMP441 MEMS microphone. Features 25+ language audio prompt packages stored in main/assets/locales/ (OGG Vorbis, ~150KB per language, ~50KB RAM footprint). Supports Chinese, English, Japanese, Russian, Spanish, and 17 newly added languages.
3️⃣ Cloud LLM & Vision Engine
Streams Opus 60ms frames over UDP/WebSocket to DeepSeek-V3, Qwen-Max, Doubao, GPT-4o, or Gemini 1.5 Pro. Integrates camera VQA via MCP self.camera.take_photo tool.
2. Usage Guide & Device Operation
Operation Manual

Follow these steps to operate the Xiaozhi AI Node after flashing firmware to your ESP32-S3 board:

1. Network & Wi-Fi Provisioning
On first boot, the ESP32-S3 starts a captive portal Wi-Fi access point (XiaoZhi-Setup). Connect via smartphone to enter your local Wi-Fi SSID and WPA2 key.
2. Voice Wake-Up & Push-to-Talk
Say "你好小智" to trigger auto VAD listening mode, or hold down the tactile switch on GPIO 00 for manual push-to-talk mode.
3. Response Interruption (Barge-In)
Press GPIO 00 button or say the wake word while the robot speaker is playing audio to immediately halt LLM response generation and open microphone input.

Section 3.1 ESP-IDF Development Environment Setup & XiaoZhi Compilation

Xiaozhi v2.x requires ESP-IDF 5.4.0 or later. If using older ESP-IDF 5.3.x versions, compilation will fail with ERROR: project depends on idf (>=5.4.0).

Terminal Commands • ESP-IDF 5.4.0 Setup & Flashing Workflow 
# 1. Clone Xiaozhi ESP32 repository
git clone --recursive https://github.com/xiaozhi-esp32/xiaozhi-esp32.git
cd xiaozhi-esp32

# 2. Set ESP32-S3 target architecture (requires ESP-IDF >= 5.4.0)
idf.py set-target esp32s3

# 3. Configure Wake Word engine & Board settings
idf.py menuconfig
# Navigate: Xiaozhi Assistant -> Board Selection -> Select your hardware board
# Navigate: Component config -> ESP Speech Recognition -> Select Wake Word ("你好小智")
# Navigate: Xiaozhi Assistant -> Language Settings -> Select Default Locale ("zh-CN" / "en-US")

# 4. Compile project, flash to ESP32-S3 over COM port, and open serial monitor
idf.py -p COM3 -b 2000000 build flash monitor
I2C Conflict Resolution & N8R2 PSRAM Fix:
If you encounter I2C bus conflicts, enter idf.py menuconfig, select Component config -> Audio Codec Device Configuration, and turn off the first option. For N8R2 boards (8MB Flash / 2MB PSRAM), change PSRAM mode from OCTAL to QUAD before building.

Section 3.2 WebSocket Communication Protocol

In WebSocket mode, both control JSON messages and binary Opus audio frames are transmitted over a single full-duplex WebSocket connection (port 443 WSS).

WebSocket JSON Protocol • Hello Handshake & Text Streaming 
// 1. Client -> Server: WSS Handshake Initiation
{
  "type": "hello",
  "version": 3,
  "transport": "websocket",
  "audio_params": { "format": "opus", "sample_rate": 16000, "channels": 1, "frame_duration": 60 }
}

// 2. Server -> Client: Text Delta Response & Emotion Token
{
  "type": "llm",
  "text": "Hello! How can I assist your robotics task today?",
  "emotion": "smile"
}

// 3. Audio Streaming: Sent as raw binary WebSocket frames containing 60ms Opus audio packets.

Section 3.3 MQTT + UDP Hybrid Communication Protocol Documentation

Separates signaling into MQTT JSON control messages and audio data into AES-CTR encrypted UDP packets:

Binary Packet Header • Encrypted UDP Opus Audio Packet 
|  Type (1B)  |  Flags (1B)  | Payload Len (2B) | SSRC (4B) | Timestamp (4B) | Sequence (4B) | Encrypted Payload (N Bytes) |
|   0x01      |    0x00      |     Network      |  Sync Src |   Network Byte  | Monotonic Seq  |    AES-CTR Encrypted Opus   |

Field Definitions:
- Type: Fixed 0x01 for Audio Stream Data
- Payload Length: Length of encrypted payload (Big-Endian Network Byte Order)
- Sequence: Monotonically increasing counter for replay protection & packet ordering
- Encryption: AES-128-CTR with key & nonce supplied during MQTT Hello handshake
