1. Core AI Architecture & Hybrid Inference
Edge + Cloud + IoT

Xiaozhi AI operates on a Hybrid AI Architecture: low-latency edge processing on the ESP32-S3 handles instantaneous voice wake-up and local keyword filtering, while complex natural language understanding, reasoning, and speech synthesis are offloaded to high-performance cloud Large Language Models (LLMs).

1. Local Voice Wake-Up
Runs Espressif's Wake Word Engine locally on dual ESP32-S3 LX7 cores at 240MHz. Latency <200ms with <5mA standby power. Default wake phrase: "你好小智" (supports 26+ custom wake words).
2. ASR & Cloud LLM Engine
Captures 16kHz mono audio via INMP441 MEMS microphone, compresses it using Opus 60ms frames, and streams over UDP to cloud ASR. Feeds prompt to DeepSeek, Qwen-Max, Doubao, or GPT-4o for instant reasoning.
3. TTS Synthesis & Emotion Tokens
Synthesizes warm human voice (Azure/Baidu TTS) played back via MAX98357A I2S amplifier, while simultaneously extracting independent emotion tokens (e.g. emotion: smile) for display on the SSD1306 screen.
4. MCP Robot Node Control
Translates natural spoken commands ("Raise robot arm", "Check battery status") into structured Model Context Protocol (MCP) JSON tool calls to actuate servos, motors, and peripheral robot nodes.
2. MQTT + UDP Hybrid Communication Protocol
Dual Channel Protocol

To guarantee real-time voice response without audio stuttering, Xiaozhi AI separates signaling and data into two distinct channels:

Protocol Lifecycle & Handshake Flow
STEP 01 • MQTT CONNECT
MQTT Control Link
Device establishes secure MQTT connection to server (KeepAlive: 240s, ClientId, Auth credentials).
STEP 02 • HELLO EXCHANGE
Audio Channel Request
Device sends "type": "hello" JSON with audio params (Opus, 16kHz, 60ms). Server returns UDP port, AES key & nonce.
STEP 03 • UDP AES-CTR INIT
UDP Audio Channel
Device initializes 128-bit AES-CTR encryption context using negotiated udp.key and udp.nonce.
STEP 04 • OPUS STREAMING
Real-Time Audio Loop
Bi-directional compressed Opus audio packets stream over UDP with sequence & timestamp protection.

Protocol Payloads & Packet Structure

JSON Protocol • MQTT Hello Handshake Exchange 
// 1. Device -> Server: Request Audio Channel setup
{
  "type": "hello",
  "version": 3,
  "transport": "udp",
  "features": { "mcp": true },
  "audio_params": {
    "format": "opus",
    "sample_rate": 16000,
    "channels": 1,
    "frame_duration": 60
  }
}

// 2. Server -> Device: Audio Channel Configuration & AES Credentials
{
  "type": "hello",
  "transport": "udp",
  "session_id": "sess_883a91b2c4",
  "audio_params": { "format": "opus", "sample_rate": 24000, "channels": 1, "frame_duration": 60 },
  "udp": {
    "server": "192.168.1.100",
    "port": 8888,
    "key": "0123456789ABCDEF0123456789ABCDEF",
    "nonce": "0123456789ABCDEF0123456789ABCDEF"
  }
}
Binary Packet Header • Encrypted UDP Opus Audio Packet 
|  Type (1B)  |  Flags (1B)  | Payload Len (2B) | SSRC (4B) | Timestamp (4B) | Sequence (4B) | Encrypted Payload (N Bytes) |
|   0x01      |    0x00      |     Network      |  Sync Src |   Network Byte  | Monotonic Seq  |    AES-CTR Encrypted Opus   |

Field Definitions:
- Type: Fixed 0x01 for Audio Stream Data
- Payload Length: Length of encrypted payload (Big-Endian Network Byte Order)
- Sequence: Monotonically increasing counter for replay protection & packet ordering
- Encryption: AES-128-CTR with key & nonce supplied during MQTT Hello handshake

6. Model Context Protocol (MCP) & Smart IoT Control
AI-to-Hardware Control

The Model Context Protocol (MCP) enables the Xiaozhi AI assistant to convert spoken human intents into concrete hardware actions across all Prayas V1 robot nodes (e.g. driving motors, setting servo angles, reading telemetry sensors).

JSON Protocol • MCP Async Tool Call Executed by ESP32 
// Server -> ESP32: Invoking registered hardware function tool
{
  "type": "mcp",
  "payload": {
    "action": "call_tool",
    "tool_name": "set_servo_angle",
    "arguments": {
      "node_id": "node-02",
      "servo_channel": 1,
      "angle_degrees": 90
    }
  }
}

// ESP32 -> Server: Execution Result Callback
{
  "type": "mcp",
  "payload": {
    "status": "success",
    "tool_name": "set_servo_angle",
    "result": { "status": "OK", "current_angle": 90 }
  }
}
7. DIY Step-by-Step Compilation & Build Guide
ESP-IDF Setup

Follow these steps to configure the ESP-IDF build environment and flash the Xiaozhi firmware to your ESP32-S3 development board.

Terminal Commands • ESP-IDF Compilation & Flashing Workflow 
# 1. Clone Xiaozhi ESP32 repository
git clone --recursive https://github.com/xiaozhi-esp32/xiaozhi-esp32.git
cd xiaozhi-esp32

# 2. Set ESP32-S3 target architecture
idf.py set-target esp32s3

# 3. Configure Wake Word engine & Board settings
idf.py menuconfig
# Navigate: Component config -> ESP Speech Recognition -> Select Wake Word ("你好小智")
# Navigate: Xiaozhi Assistant -> Language Settings -> Select Default Locale ("zh-CN" / "en-US")

# 4. Build firmware project
idf.py build

# 5. Flash to ESP32-S3 board and open monitor terminal
idf.py -p COM3 flash monitor
Important Configuration Note for N8R2 Boards (8MB Flash / 2MB PSRAM):
If using N8R2 instead of N16R8, open menuconfig and change PSRAM working mode from OCTAL to QUAD, set Flash size to 8MB, and point the custom partition table to partitions_8M.csv before compiling.
