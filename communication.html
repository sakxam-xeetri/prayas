1. Unified 5-Input Control System Architecture

Rather than creating separate control paths for voice, web, or remote control, PRAYAS routes all 5 input methods into a single Master Command Manager running on the Master ESP32. Each control method converts user intent into a standardized high-level PRAYAS command packet.

A. Voice / AI Control

ESP32-S3-CAM

The ESP32-S3-CAM AI Node listens via microphone and I2S audio interface, running Xiaozhi VQA LLM. When a speech command like "Look left and wave" is parsed, the AI node generates high-level PRAYAS commands (CMD=HEAD_LEFT) and transmits them over ESP-NOW to the Master.

Flow: Mic ➔ I2S Audio ➔ AI Node ➔ High-Level Command ➔ ESP-NOW ➔ Master

B. Remote Internet Control

VPS + MQTT

Allows controlling PRAYAS from anywhere across the globe. Remote web browser sends commands via HTTPS/WebSocket to a Cloud VPS hosting an MQTT broker (prayas/cmd/motor). The Master ESP32 subscribes to the topic over Wi-Fi and executes the commands.

Flow: Web Dashboard ➔ HTTPS ➔ VPS ➔ MQTT Broker ➔ Wi-Fi ➔ Master ESP32

C. Physical / Gamepad Controller

Direct 2.4GHz

Provides ultra-low latency direct joystick control for field operation. The wireless receiver connects directly to the Master ESP32 GPIO/UART. Requires zero internet access or external routers, ensuring instantaneous responsiveness.

Flow: Gamepad Joystick ➔ Receiver ➔ Direct Serial/GPIO ➔ Master ESP32

D. Local Web Control UI

ESP32 Hosted AP

The Master ESP32 hosts its own local SoftAP Wi-Fi network and web server. Phones or laptops connect directly to 192.168.4.1 to access an interactive web dashboard with joysticks, pose triggers, and live telemetry over WebSocket.

Flow: Mobile Browser ➔ Local Wi-Fi ➔ ESP32 WebServer/WebSocket ➔ Master

E. Autonomous Wandering Logic

Sensor Fusion

When set to Autonomous Mode, the Master decision algorithm computes navigation paths based on real-time IMU data from the Sensor Node (MPU6050), obstacle readings, and vision prompts from the AI camera node.

Flow: MPU6050 / Camera ➔ Sensor Node ➔ Decision Engine ➔ Master

2. Master Control Manager & Priority Hierarchy

To prevent conflicting inputs (e.g. AI attempting to walk forward while a physical controller sends a Stop command), the Master ESP32 executes a strict Command Priority Engine and maintains global system operating modes.

Command Priority Engine

Higher priority commands immediately preempt lower priority commands. Safety and physical controls always take precedence over voice and autonomous routines.

PRIORITY 1 EMERGENCY STOP Immediate hard stop across all 4 motors and lock servos into safe resting pose.

PRIORITY 3 PHYSICAL GAMEPAD Direct 2.4GHz controller manual joystick input preempts cloud and web commands.

PRIORITY 5 LOCAL WEB UI Local AP Wi-Fi control dashboard user interaction.

3. ESP-NOW Wireless Mesh & Subsystem Execution

ESP-NOW is a connectionless 2.4GHz wireless protocol developed by Espressif. It allows quick, low-latency, peer-to-peer packet transmission (sub-10ms latency) without requiring a Wi-Fi router.

NODE 0x02 • MOTOR NODE (ESP32)

4x Johnson Motors + BTS7960

Receives movement commands (FORWARD, BACKWARD, SPEED_CONTROL). Manages PWM and direction signals locally. Monitors INA219 current draw.

Local Obstacle Protection: Even if Master sends FORWARD, the Motor Node checks front IR sensors locally. If obstacle detected, it immediately halts motors and replies OBSTACLE_STOP to Master.
NODE 0x03 • SERVO NODE (ESP32)

7x MG995 Servos + PCA9685

Instead of receiving raw individual servo angles on every tick, the Servo Node stores 3-tier command abstractions:

  • Level 1 (Position): Servo ID + Angle (Calibration)
  • Level 2 (Pose): REST, HAND_DOWN, HEAD_CENTER
  • Level 3 (Workflow): Multi-step smooth motion sequences (WAVE, GREETING).
NODE 0x04 • SENSOR NODE (NANO)

MPU6050 IMU + DHT11

Provides continuous telemetry to Master over I2C/Serial. Transmits accelerometer/gyroscope motion orientation, tilt angle, ambient temperature, and humidity readings.

Telemetry Payload: IMU Pitch/Roll, Temp °C, Humidity %, Motion Delta

Every protocol in PRAYAS CYRUS is assigned a specific operational layer. High-level web protocols manage internet connectivity, ESP-NOW handles low-latency robot messaging, and peripheral buses manage hardware components.

6. Safety, Watchdogs & Fault Tolerance

Operating 4 high-torque motors and 7 MG995 servos requires complete fail-safe mechanisms. Every node features an independent hardware/software watchdog to prevent unintended motion during packet loss or internet disconnection.

Heartbeat Watchdog (500ms)

The Motor Node expects a valid control packet or heartbeat ping from Master at least once every 500 ms. If signal is lost, the Motor Node automatically cuts motor PWM power to 0, halts movement, and enters SAFE mode.

Offline Internet Resilience

If internet or Cloud VPS disconnects, ESP-NOW internal robot mesh continues functioning seamlessly. Local gamepad, local Wi-Fi AP dashboard, voice AI, and local IR obstacle safety remain 100% operational offline.

Command Acknowledgement

Long multi-step workflows (e.g. GREETING pose) send an ACK back to Master upon receipt, followed by a WORKFLOW_COMPLETE status packet once finished.
